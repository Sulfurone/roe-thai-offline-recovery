# 游戏画面中的离线控制菜单

`start_ingame_control.cmd` 将原生飞机/手动跳伞与白天、**Windows 本机悬浮菜单**组合；用户已确认“白天飞行、跳伞和落地移动都正常”。已确认的白天地面菜单保留在 `start_ingame_ground.cmd`。菜单贴在游戏窗口上，提供天气、武器、装备和多车型选择，是独立叠加窗口。菜单显示、F6 展开／收起与下拉选择也已实机确认。

当前反馈（2026-10-29）：用户已确认鼠标菜单可见，但F6仍不能控制。游戏右上方有小型“离线控制”入口，点击打开大菜单，点击收起或Esc返回游戏。小入口设置为不激活窗口，不应自动夺取键盘焦点；大菜单不因落地或状态刷新自行展开。快捷键问题仍未解决，历史F6正常结论不代表当前版本已通过。最新源码入口文字为“离线控制 · 点击”，当前运行的一轮仍可能显示较早“离线控制 · F6”字样。

用户报告的偶发下车问题已自行恢复，并要求不用修复；候选下车恢复按钮及相关服务变更已全部撤回，不包含在菜单中。

## 使用

最新反馈指出飞机横飞、步行后刷新坐标滞留。当前主入口已启用两个修复候选：按航线调整飞机生成旋转，并确认完整移动包的序号、使用最后轨迹点。119项本地测试和原生参数验证通过；新画面和步行刷物效果等待重启验收。此前“正常”确认的范围是白天飞行、离机、落地移动。

1. 退出已有游戏和旧服务，运行 `start_ingame_control.cmd`。需要 Windows、带 Tcl/Tk 的 Python 3.10+，以及自行生成的本地协议材料。
2. 新入口在地图载入阶段生成原生飞机，等待角色就绪与 2 秒登机延迟后沿西→东航线飞行，使用游戏原有离机操作跳伞。菜单开始完全隐藏，保留游戏焦点；按 F6 打开，再按 F6 或 Esc 关闭。地面入口仍直接从地图地面开始。
3. 首个有效角色位置后 3 秒设置一次正午（12）；登录与环境消息先统一时间基准。地面入口的白天、移动和视角，以及主入口的白天飞行、跳伞和落地移动均已实机确认。昼夜时间与天气独立，不会覆盖手动选择的天气。
4. “天气”可选择24个原生状态及过渡时间。“武器”可选20种枪械与配套弹药。“装备”可选药品、头盔、防弹衣、背包、投掷物和配件，每次一件。“载具”可选8种原配置并查看最近已发送车辆的位置，总数最多16辆。请落地后刷新。配件在原背包内拖到兼容枪械对应槽；本轮安装/拆卸候选待实机，药品使用、完整伤害与投掷仍待恢复，详见[装备操作说明](../EQUIPMENT_ACTIONS.md)。
5. 点击操作后等待回执，再收起菜单返回游戏。武器在附近地面生成，需要使用游戏原有拾取交互。

菜单使用本轮本地文件邮箱，不启动HTTP或浏览器。菜单本身仍是独立窗口；当前主入口另加载[只读脚点观测模块](../POSITION_STREAMING.md)，原DLL按哈希备份、转发及恢复。旧“整个主入口不加载模块/不读内存”的描述已过时。菜单随游戏窗口隐藏或退出，原稳定跳伞隔离入口保持原配置。

“已发送”表示数据已进入游戏连接。用户已确认菜单显示/选择、所测试物品拾取，以及2026-10-28第五轮所测试车辆上车/驾驶/下车正常；全部物品、车型/座位和天气视觉仍按各自范围验收。

## 输入和窗口修复

2026-10-29用户报告落地时菜单弹出打断操作。当前候选对全部游戏入口默认隐藏Tk窗口，初始化立即withdraw，地图就绪/落地/切回游戏不会自动显示或强制取焦点；只有主动F6/菜单按钮可展开，关闭后完全隐藏。`--collapsed`保留兼容，正常游戏已统一隐藏；`--preview`仍显示独立预览。

第一轮用户确认不再自动弹出，但F6不能打开；当时收到WM_HOTKEY却未进入toggle，随后300秒限时诊断服务结束。第二版增加同一游戏进程及根窗口的焦点识别，焦点进入时清除过期按键，恢复短按低位与按下沿，记录F6_INACTIVE便于排查。最终候选未获用户实机复验，不能沿用较早F6正常反馈宣称本次已验收。32项菜单生命周期/邮箱/加密游戏会话检查通过，使用替身窗口验证，不替代实际焦点或下拉操作。

- 部分游戏输入模式未向菜单交付 `WM_HOTKEY`，增加仅针对 F6 的键状态检测，并对两路事件去重；保留鼠标按钮。修复后用户确认 F6 正常。
- 状态刷新曾每 200 毫秒执行 `wm deiconify`，使下拉框闪退。现在仅在窗口确实隐藏时显示，且下拉展开期间不改变位置和显示状态。用户确认下拉和选择恢复正常。
- 不在定时刷新中反复重置按钮状态，避免干扰鼠标操作。
- 菜单新增服务器收到的当前位置（米）；步行后可以用F6核对坐标是否变化。刷新记录在服务日志中带有实际使用的角色坐标。
- 独立界面预览：`python ingame_overlay.py --preview`。预览按钮禁用，不连接游戏。

## 服务与验证

早先只延迟正午设置仍导致卡死：旧登录样本服务器时间为0，后续时钟为真实epoch。原生回调模拟复现约负17亿秒的异常偏移。现在只在发送时同步登录时间，不写原始样本，再发送正午时钟。使用世界样本设置昼夜时，必须明确`--world-time-tail-bytes`布局；本入口使用经过原生验证的历史18字节尾部。修正后的地面白天与主入口的白天飞行、跳伞、落地移动均获用户实机确认；后续所测试物品拾取与第五轮车辆上车/驾驶/下车也已确认。天气视觉、全部物品及车型/座位仍按各自范围验收。

`--ingame-overlay` 创建本轮 `IngameMailbox`，再启动菜单子进程。`MailboxClient` 校验状态、限定整数参数和递增序号，并等待上一操作回执。游戏线程调用现有 `ControlSession`，使用本轮 TPDU/AES 密钥发送消息。退出、未就绪、乘车、刷物数量上限等检查仍在服务端执行。

`ingame/RoeControlPanel.lua` 与 `bootstrap.lua` 仅通过 Lua 5.1 模拟。只读分析确认 `/lua` 和 `_GM_CONTROL_` 存在，不证明调试入口可用，也不证明某个快捷键。

Lua 试验运行期间仅新增四个自有文件：根目录和 `Data/ScriptCustom` 下的 `ROE_OfflineMenu.lua`、`Data/ScriptCustom/LoadConfig.lua`、缺失时的 `FileDriven/_GM_CONTROL_`。已有文件碰撞拒绝，原 EXE/DLL/SFC 不改动。服务正常结束只清理本轮创建且哈希匹配的文件；用户修改的文件保留。若异常中断，退出游戏后按本轮收据清理：
