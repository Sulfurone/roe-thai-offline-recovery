# 恢复方法与证据

本项目固定研究 Garena 泰服 0.2.15.5。下述地址和消息号针对这一客户端版本；其他发行版不能直接套用。完整实验先后、负例及尚未确认的判断记录在 [交接历史](../HANDOFF.md)。

## 研究路径

1. **盘点与只读提取**：`sfc_extract.py` 解析 SFC v2、独立校验每条 LZ4 记录长度并以原始键命名输出；`vfs_extract.py` 研究 VFS 目录、偏移和解压。输出保存在本地 `extracted/`，不上传原版内容。
2. **协议与本地握手**：`tpdu.py` 实现 v14 帧、长度边界及 AES-CBC / tsf4g 编解码；`local_server.py` 在回环地址处理本地合成会话。以真实客户端请求、合成 socket 测试和原生解码结果交叉核对，不能把伪造的成功回复等同实际画面成功。
3. **还原结构**：`probes/` 中的反汇编、注册表与跟踪工具定位消息处理函数；`probes/native_codec_probe.py` 将自行取得的客户端映像放进受限 x86 Unicorn 环境，针对单个原版编解码函数验证消耗长度和往返结果。原映像、生成的 payload、个人角色请求和抓包不在仓库中。部分历史诊断程序会替换或修改客户端副本中的文件；它们并非启动服务的必需步骤，研究时请阅读源码、记录校验值并对自己的副本操作。
4. **逐层推进场景**：以原客户端实际收到和发出的消息为依据，先构建角色、房间和入图数据，再处理地面出生、高度、下落状态及移动。之前位置和速度错误曾造成水中卡住、悬空或移动过快；地面行走基线已在原客户端得到确认。
5. **玩法状态机**：`offline_gameplay.py`、`offline_inventory.py`、`offline_ground_loot.py`、`offline_world_state.py` 和 `offline_weapons.py` 处理实验性载具、武器弹药、背包、掉落与存档。先用合成单元测试检查数量、重复请求和存档，再用加密会话和原版编解码器验证；操作画面是否正确需单独验收。

## 开局飞行与跳伞

依据地图配置和原碰撞地形计算 4096 米水平范围，示例航线从西侧 `(200, 204800, 75000)` 到东侧 `(409400, 204800, 75000)`，单位厘米、速度 5000 厘米/秒；示例固定航向约需 82 秒，尚未还原原服随机航线。`probes/prepare_cross_map_airdrop.py` 生成对应本地场景材料；服务按时间插值并使用收到离机请求时的位置。原生解码、服务日志及离机坐标已检查；飞机全程画面、手动跳伞、开伞与转向尚需实机验证。

## 地面物品和枪弹

当前实验中 `0x0821` 创建地面单件实体，`0x3b63` 为拾取请求，`0x082b` 移除实体；`0x3e80` 包含背包操作，原客户端整件丢弃可能发送数量 0，应按整件处理。枪械射击、停止和换弹消息分别沿各自处理分支核对，具体字段和失败案例见交接历史及测试；不可将其他版本的消息名当作权威协议。

## 重建本地材料

启动脚本会读取 `private/native-roster/` 和 `private/typed-gameplay/` 的版本特定样本；它们由原客户端和个人会话推导，未分发。`profiles/`、`logs/`、`extracted/` 和 `private/` 均在忽略列表中。生成器（例如 `probes/prepare_native_defaults.py` 和 `probes/prepare_typed_gameplay.py`）展示现有依赖，但仍有需要先取得原始角色请求、原始客户端加载映像和早期基础样本的步骤；顺序及可用性需结合交接历史和各脚本检查。项目当前没有从零到可玩的一键重建脚本，欢迎补齐。

`README-research-history.md` 与 `HANDOFF.md` 是本机实验的历史快照，含过时的绝对地址、进程状态及中间推测。请以最新代码和实际测试为准，不要直接照搬历史上的进程 ID、路径或 GUI 操作。

## 历史辅助脚本

`probes/find_metalib.py` 和 `probes/historical/` 保留用于扫描结构、消息号、字符串和资源命名的早期研究工具。部分脚本保留当时的 `F:\roe` 示例路径或具体文件名，使用前需要针对自己的目录调整；它们读取本地材料，不应将输出中的客户端数据或个人会话公开。`mem_debug.py` 需要显式提供进程 ID。
